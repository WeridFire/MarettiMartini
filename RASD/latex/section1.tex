\section{Introduction} 
\subsection{Purpose}
The \textbf{Best Bike Paths (BBP)} system is a comprehensive software platform commissioned by a cyclist association to serve both its members and the broader cycling community. 

The fundamental purpose of the system is to facilitate the creation, maintenance, and utilization of a shared repository of bicycle paths. The system addresses two primary operational objectives:

\begin{itemize}
    \item \textbf{Activity Tracking:} BBP enables registered users to monitor personal cycling activities by recording trips and generating detailed statistical reports enriched with environmental variables.
    
    \item \textbf{Crowdsourced Territorial Mapping:} The platform leverages user participation to update path conditions and identify obstacles. Data acquisition is achieved through manual user reporting or automated detection via mobile device sensors.
\end{itemize}

\subsubsection{Goals} \label{goals}
This section lists the high-level objectives (Goals) that the BBP system must satisfy.

\begin{enumerate}[label=\textbf{[G\arabic*]:}]
    \item \textbf{Allow registered users to track their cycling activity}
    \\
    The system shall allow users to record their trips, archiving them to maintain a personal history of their cycling activities.

    \item \textbf{Provide detailed statistics on trip performance}
    \\
    For every recorded trip, the system must calculate and display relevant metrics, such as the total distance covered and the average speed maintained by the user.

    \item \textbf{Enrich trip data with contextual information}
    \\
    The system must integrate trip data with meteorological information (weather conditions, temperature, wind speed) retrieved from external services, relative to the time and location of the activity.

    \item \textbf{Enable manual reporting of path status}
    \\
    Registered users must be able to manually insert information regarding path segments, specifying maintenance status (e.g., optimal, requires maintenance) and the presence of obstacles.

    \item \textbf{Automate data collection via mobile sensors}
    \\
    The system must be capable of acquiring data in the background while the user is biking, using GPS for tracking and accelerometer/gyroscope to identify potential road surface anomalies (e.g., potholes).

    \item \textbf{Ensure accuracy of automatically detected data}
    \\
    Since automated detection may generate false positives, the system must require the user to confirm or correct the information detected by sensors before it is validated or published.

    \item \textbf{Enable the publication of collected information}
    \\
    Registered users must be able to explicitly mark their path data (whether manually entered or automatically detected and confirmed) as publishable, making it available to the community. Only publishable information shall be visible to other users and contribute to path scoring.

    \item \textbf{Support route planning for all users}
    \\
    The system must allow any user (even unregistered ones) to input an origin and a destination to visualize available bike paths on a map.

    \item \textbf{Evaluate and rank available paths}
    \\
    When visualizing route options, the system must calculate a score for each path based on its maintenance status and its effectiveness in reaching the destination, sorting results by quality.

    \item \textbf{Detect cycling activity automatically}
    \\
    The system must autonomously identify when the user is cycling (based on speed patterns and device telemetry) to automatically trigger trip recording and sensor data collection.

    \item \textbf{Protect user privacy while enabling collaboration}
    \\
    The system must maintain a clear distinction between private user data (personal trip history and statistics) accessible only to the owner, and publishable path information that contributes to the shared inventory.
\end{enumerate}

\subsection{Scope}
The \textbf{Best Bike Paths (BBP)} is a software system commissioned by a biker's association to support cyclists in creating, maintaining, and accessing a collaborative inventory of bike paths.
The system aims to enhance the cycling experience by enabling users to:
\begin{itemize}
    \item Record and track their cycling activities with detailed statistics;
    \item Contribute to a community-driven database of bike path conditions;
    \item Access optimized route recommendations based on real-time path quality data.
\end{itemize}

Following the \textit{Problem Frames} approach, we distinguish between:
\begin{description}
    \item[The World (Environment):] The physical and social context in which the system operates, including cyclists, physical bike paths, environmental conditions, and mobile devices.
    \item[The Machine (BBP System):] The software system itself, including the mobile application, backend services, databases, and integration layers.
\end{description}

\subsubsection{World Phenomena}
These are events or states that exist continuously in the real world, independent of the software system.

\begin{enumerate}[label=\textbf{[WP\arabic*]}:]
    \item A cyclist travels along a physical route.
    \item A physical obstacle (e.g., a pothole) exists or appears on a path.
    \item The physical condition of a path deteriorates or improves (status change).
    \item Meteorological conditions (temperature, wind, rain) occur at a specific geographical location.
\end{enumerate}

\subsubsection{Shared Phenomena}
These describe the interactions between the World (Environment) and the Machine (The BBP System).

\paragraph{Controlled by the World, Observed by the Machine}
These are inputs or events triggered by actors (Users, Sensors, External Services) that the BBP system detects.

\begin{enumerate}[label=\textbf{[WM\arabic*]}:]
     \item A Registered User initiates or terminates the recording of a trip via the mobile application.
    \item Mobile device sensors transmit telemetry data (GPS coordinates, speed, accelerometer and gyroscope readings) to the system.
    \item A Registered User manually inputs path data (street names, path status).
    \item A Registered User submits a confirmation or correction regarding an automatically detected anomaly (e.g., confirming a pothole).
    \item An Unregistered or Registered User submits a query for a bike path specifying an origin and destination.
    \item The External Weather Service transmits meteorological data upon request.
    \item A Registered User marks path information as publishable.
    \item A Registered User requests to view their trip history.
    \item A User submits authentication credentials (registration or login data).
\end{enumerate}

\paragraph{Controlled by the Machine, Observed by the World}
These are outputs or actions taken by the BBP system that actors in the world can perceive.

\begin{enumerate}[label=\textbf{[MW\arabic*]}:]
    \item The System visualizes trip statistics (total distance, average speed, performance metrics) to the User.
    \item The System displays weather-enriched trip details to the User.
    \item The System presents a request for verification of a detected anomaly to the Registered User.
    \item The System renders a map visualizing the recommended bike path(s) ranked by score.
    \item The System displays the consolidated status (e.g., ``optimal'', ``requires maintenance'') of a specific path segment.
    \item The System notifies the User when automatic trip recording is activated or deactivated based on detected cycling speed.
    \item The System displays a chronological list of the User's previously recorded trips with associated statistics.
    \item The System sends a request for weather conditions to the External Weather Service.
\end{enumerate}
